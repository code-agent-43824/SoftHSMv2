# PLAN — этап 7: юнит-тесты на ГОСТ 2012

Легенда: `[ ]` не начато, `[~]` в работе, `[x]` сделано, `[!]` заблокировано.

## Действия

- [ ] Юнит-тесты на `BotanStreebog256`: контрольные векторы ГОСТ Р 34.11-2012
      для 256 бит.
- [ ] Юнит-тесты на `BotanGOST2012KeyGenerator`: генерация ключевой пары,
      параметры кривой, сериализация.
- [ ] Юнит-тесты на `BotanGOST2012Signer`: подпись и проверка, в том числе
      отрицательные случаи.
- [ ] Прогонять локально: `ctest --test-dir build --output-on-failure`. CI
      юнит-тесты не вызывает — это осознанное решение владельца.

## Не делаем

- **Восстанавливать удалённые джобы CI — не нужно.** Форк тупиковый, собирать
  конфигурации, которые мы не поставляем, незачем.
- **Приводить в порядок апстримные документы — не нужно.**
- **Трогать старые коммиты — нельзя** (§5, история append-only). 21 коммит от
  1–11 августа остаётся как есть; конвенция соблюдается начиная с `2ff7bd0`.

## Закрытые этапы

- **Этап 5** — правила и проектные документы.
- **Этап 6** — проверка на реальном стенде. Сборки Windows x86, x64 и ARM64
  проверены владельцем вручную и тест-китом. Отказ, найденный по дороге,
  оказался посторонними копиями `softhsm2.dll` в системных каталогах, а не
  дефектом проекта; попутно укреплён поиск профиля пользователя на Windows.
