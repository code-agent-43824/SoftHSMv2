- [~] **Заводские PIN должны выглядеть заводскими.** Решение владельца 29.09
      заменяет решение от 14.08. Токен с заводскими PIN — user `12345678`,
      SO `87654321` — не получает `TOKEN_FLAGS_USER_PIN_NOT_DEFAULT` и
      `TOKEN_FLAGS_ADMIN_PIN_NOT_DEFAULT` в `C_EX_GetTokenInfoExtended`; после
      смены PIN соответствующий флаг ставится. Сейчас флаги выводятся из
      `CKF_TOKEN_INITIALIZED` и `CKF_USER_PIN_INITIALIZED`
      (`src/lib/SoftHSM.cpp:1148–1152`) и стоят на любом инициализированном
      токене — на стенде 28.09 клиентское ПО прочитало так заводские
      `12345678`/`87654321` как сменённые (JOURNAL за 28.09). Значение PIN
      известно только в момент установки — `C_InitToken`, `C_InitPIN`,
      `C_SetPIN`, — поэтому признак вычислять там и хранить в токене.
      **Снято с устройства 03.10** (JOURNAL): на заводских PIN оба флага `0`;
      после `C_SetPIN` на другой PIN `USER_PIN_NOT_DEFAULT = 1`; после смены
      **обратно на заводское значение** флаг снова `0` — то есть устройство
      сравнивает PIN с заводским значением, а не «менялся ли». Плюс на
      заводском PIN стоит `CKF_USER_PIN_TO_BE_CHANGED` в `C_GetTokenInfo` и
