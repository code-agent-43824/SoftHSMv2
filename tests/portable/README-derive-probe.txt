Проба CKM_GOSTR3410_12_DERIVE на Рутокене — rutoken-derive-probe
===============================================================

Что это
-------
Неинтерактивная программа, которая за один прогон снимает с живого Рутокена
через библиотеку Актив, как устройство отвечает на C_DeriveKey с
CKM_GOSTR3410_12_DERIVE (0xD4321007). Этим вызовом Рутокен Плагин
расшифровывает ГОСТ 28147-89. Форк уже отвечает на точный вызов из трассы
плагина; всё остальное он отвергает, пока не известно, что делает
устройство (docs/PLAN.md, часть 2). Весь вывод — один текстовый лог (stdout).

Исходник: tests/portable/rutoken-derive-probe.c в репозитории SoftHSMv2.
Бинарник собран под Linux x86-64 (glibc 2.34+, Ubuntu 22.04 и новее),
зависит только от libc.

  SHA-256: <см. sha256.txt>

Как запускать
-------------
Токен должен быть один (или укажите --slot). Нужен только PIN пользователя.
Путь к библиотеке поправьте под ваш пакет.

  chmod +x rutoken-derive-probe
  ./rutoken-derive-probe /usr/lib/librtpkcs11ecp.so --user-pin 12345678 \
      > derive-probe.log 2>&1

PIN можно передать через переменную окружения, чтобы он не попал в историю
оболочки:

  export P11_USER_PIN=12345678
  ./rutoken-derive-probe /usr/lib/librtpkcs11ecp.so \
      --user-pin-env P11_USER_PIN > derive-probe.log 2>&1

Флаги:
  --user-pin PIN         PIN пользователя (по умолчанию 12345678)
  --user-pin-env ИМЯ     взять PIN пользователя из переменной окружения
  --slot N               слот (по умолчанию — первый с токеном)

Код выхода 0 — прогон дошёл до конца. Отказы устройства — это данные, а не
ошибки пробы: они записываются в лог, и прогон продолжается.

Безопасность
------------
  - Токен не форматируется, SO PIN не нужен и не используется.
  - Одна попытка входа PIN пользователя. Если PIN неверный, проба
    останавливается сразу и ничего не меняет — повторять с другим PIN
    вслепую не надо, счётчик попыток у токена общий.
  - Проба создаёт на токене ключевые пары ГОСТ-2012 (256 и 512 бит) с меткой
    «CryptoMost derive probe» и удаляет их в конце. Остатки прерванного
    прогона с той же меткой удаляются в начале следующего.
  - Выработанные ключи живут секунды: значение читается и объект сразу
    удаляется. Те немногие, что создаются на токене (CKA_TOKEN = TRUE),
    тоже несут метку пробы.
  - В лог попадают открытые точки ключей пробы и выработанные значения. Это
    одноразовые ключи пробы, ваших ключей проба не касается.

Что присылать назад
-------------------
  - derive-probe.log целиком.

Разделы лога
------------
  1  библиотека, токен; C_GetMechanismInfo для 0xD4321007, 0x1204 и
     CKM_GOST_KEG
  2  точный вызов плагина: ключ TC26-A на токене, плоский параметр 84 байта,
     CKD_NULL, UKM 8 байт, шаблон CKO_SECRET_KEY / CKK_GOST28147 /
     CKA_TOKEN = FALSE; все атрибуты результата; тот же вызов с UKM в
     обратном порядке байт. Точка отправителя — открытая половина
     опубликованного ключа ТК 26, поэтому значение пересчитывается офлайн
     по открытой точке ключа токена, которая тоже печатается
  3  согласие двух сторон на CryptoPro-A/B/C и TC26-A; примет ли токен
     импорт опубликованного закрытого ключа ТК 26
  4  другие kdf, длины UKM, нулевой UKM
  5  параметр структурой CK_GOSTR3410_DERIVE_PARAMS, NULL, короткий и
     длинный буфер, точка 128 байт, точка не на кривой
  6  другие шаблоны результата: CKA_VALUE_LEN, CKA_GOST28147_PARAMS,
     CKA_SENSITIVE, CKA_EXTRACTABLE, CKA_TOKEN, CKK_GENERIC_SECRET, Магма,
     Кузнечик
  7  ключи 512 бит (TC26 paramSetC): какой ответ и какой длины
  8  базовый ключ без CKA_DERIVE, открытый ключ как базовый,
     CKM_GOSTR3410_DERIVE (0x1204)
  9  уборка
