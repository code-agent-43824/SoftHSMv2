Проба расширений Rutoken ECP, версия 2 — rutoken-ext-probe
==========================================================

Что это
-------
Неинтерактивная программа, которая за один прогон снимает с живого Рутокена
через библиотеку Актив поведение расширенных функций, которые батарея
(portable-token-e2e) должна проверять в двух профилях (эмулятор-форк и
настоящее железо). Весь вывод — один текстовый лог (stdout); каждый DER,
который выдаёт токен (CSR, конверты CMS, сертификаты пробы), пишется в
каталог --dump-dir, каждый прочитанный журнал печатается в hex.

Все ключи генерируются на токене, все сертификаты подписываются самим
токеном — сырой импорт закрытого ключа не нужен. Зависит только от libc.

Что изменилось против первой версии
-----------------------------------
  - Сертификаты, которые строит проба, в первой версии были собраны неверно
    (пропущен уровень SEQUENCE в расширениях X.509). Отсюда CKR_ARGUMENTS_BAD
    у C_EX_PKCS7Sign во всех режимах — дело было в пробе, не в библиотеке.
    Теперь сертификаты проверены комплектным OpenSSL с ГОСТ: загружаются,
    цепочка сходится.
  - «Нет входа» для C_EX_CreateCSR теперь проверяется честно: приложение
    делает C_Logout, ключ — с CKA_SIGN=true.
  - CKA_TRUSTED ищется по классу и CKA_ID, а не первым из найденных объектов.
  - Журнал сравнивается по содержимому, а не только по длине.
  - C_EX_TokenManage вызывается с CKU_USER (в первой версии из-за ошибки
    уходил CKU_SO) и в тех режимах, что в pkcs11-tool форка OpenSC:
    force-user-pin-change и standard-default-user-pin.
  - Локальный PIN проверяется так, как это делает устройство: смена по его
    текущему значению, отказ при попытке сменить существующий PIN
    PIN-кодом пользователя.

Исходник: tests/portable/rutoken-ext-probe.c в репозитории SoftHSMv2.
Бинарник собран под Linux x86-64 (glibc 2.34+, Ubuntu 22.04 и новее).

  SHA-256: <см. sha256.txt>

Как запускать
-------------
Токен должен быть один. Перед прогоном — заводское состояние (как у вас
после rtadmin format). Путь к библиотеке поправьте под ваш пакет.

  chmod +x rutoken-ext-probe

  # рекомендуемый прогон: всё, включая форматирование обратно в заводское
  # состояние в конце (PIN-коды после формата = те, что указаны ниже)
  ./rutoken-ext-probe /usr/lib/librtpkcs11ecp.so \
      --user-pin 12345678 --so-pin 87654321 --format --dump-dir dump \
      | tee ext-v2.log

Если у токена другие PIN, укажите их в --user-pin / --so-pin. Формат в конце
выставит те же PIN (или --final-user-pin / --final-so-pin, если нужно другое).

restore-factory-defaults вместо C_EX_InitToken (по желанию):

  export EMITENT_KEY=<64 hex-символа, 32 байта ключа эмитента>
  ./rutoken-ext-probe /usr/lib/librtpkcs11ecp.so \
      --user-pin 12345678 --so-pin 87654321 --format --restore-factory \
      --emitent-key-env EMITENT_KEY --dump-dir dump | tee ext-v2.log

Вызов повторяет pkcs11-tool форка OpenSC: C_EX_SlotManage с
MODE_RESTORE_FACTORY_DEFAULTS, авторизация текущим SO PIN, параметры
форматирования как у rtadmin, НОВЫЙ ключ эмитента — тот, что вы передали,
тип Кузнечик (--emitent-magma для Магмы), 10 попыток. Ключ берётся только из
переменной окружения и в лог не попадает.

Флаги:
  --user-pin PIN / --so-pin PIN           текущие PIN (по умолчанию 12345678 / 87654321)
  --user-pin-env ИМЯ / --so-pin-env ИМЯ   взять PIN из переменной окружения
  --dump-dir КАТАЛОГ                      писать DER в КАТАЛОГ
  --write                                 локальный PIN, token-manage, CKA_TRUSTED
  --format                                --write + в конце формат в заводское состояние
  --final-user-pin / --final-so-pin PIN   PIN после формата (по умолчанию — текущие)
  --restore-factory                       формат через restore-factory-defaults
  --emitent-key-env ИМЯ                   ключ эмитента для --restore-factory (hex)
  --emitent-magma                         ключ эмитента — Магма, не Кузнечик

Безопасность
------------
  - Неверных попыток SO PIN проба не делает вообще.
  - Одна неверная попытка PIN пользователя — сразу снимается
    C_EX_UnblockUserPIN под SO.
  - Одна неверная попытка локального PIN №3 (из 10).
  - Раздел token-manage меняет PIN пользователя и возвращает его обратно;
    если устройство откажет вернуть (история PIN), это будет в логе, а
    --format в конце всё равно выставит заданные PIN.
  - Без --format созданные объекты удаляются, но локальный PIN №3 остаётся —
    тогда отформатируйте токен rtadmin, как обычно.

Лог pcscd (если понадобится APDU-трасса)
----------------------------------------
Нужен только если какой-то вызов неожиданно падает и надо понять, доходит ли
дело до карты. В обычном прогоне не нужен.

  1. Остановить штатный демон:        sudo systemctl stop pcscd pcscd.socket
  2. Запустить в отладке в своём окне: sudo pcscd -f -d -a 2>pcscd.log
  3. В другом окне — прогон пробы, как выше.
  4. Ctrl-C в окне pcscd, затем:       sudo systemctl start pcscd.socket pcscd

В pcscd.log есть APDU проверки PIN (тестовые PIN этого токена) — если это
важно, учитывайте при пересылке.

Что присылать назад
-------------------
  - ext-v2.log целиком;
  - каталог dump/ целиком (*.der).

Разделы лога
------------
  1  идентификация: библиотека и версия, токен, флаги, счётчики
  2  C_EX_CreateCSR: ГОСТ-256 (CryptoPro-A и TC26-A), ГОСТ-512, RSA;
     синтаксис DN (короткие имена, OID, ИНН/ОГРН/СНИЛС, кириллица, E),
     расширений (keyUsage, EKU, политики, subjectSignTool …) и атрибутов;
     негативы, в том числе «без входа»
  3  ГОСТ CMS: attached / без явного ключа / без цепочки / detached /
     hw-hash / detached+hw-hash / несовпадение ключа; проверки: доверенный
     корень, подделка, чужой CA, флаги CHECK_SIGNATURE_ONLY,
     ALLOW_PARTIAL_CHAINS, DO_NOT_USE_INTERNAL_CMS_CERTS
  4  RSA CMS
  5  журнал: две подписи ГОСТ-256, подпись с хешированием на токене,
     ГОСТ-512, RSA — hex каждой записи
  6  CKA_EXTRACTABLE, приватный CKA_VALUE, CKA_TRUSTED (под SO, после
     переоткрытия), USE_TRUSTED_CERTS_FROM_TOKEN до и после доверия
  7  C_EX_UnblockUserPIN; force-user-pin-change и standard-default-user-pin
  8  локальный PIN №3: создание, смена по значению, отказы, статус 3..31
  9  C_EX_InitToken: отказ при политике 0, при открытой сессии; формат;
     состояние после формата (объекты, флаги, журнал, вход новыми PIN)
